# v0.4.3 リポジトリレビュー: 改善・機能追加提案

対象: 閉域 Windows 端末向け「声の広報 テキスト読み上げツール」

- 現状は **v0.4.3 まで実機テスト済み**。
- 本提案は、既存 backlog（#49b, #50, #51）に加えて、次の開発サイクルで着手しやすい項目を整理したもの。
- 目的は「運用安定性」「品質の見える化」「保守性向上」「現場 UX 改善」。

---

## 1) 優先度A（次リリース候補: v0.4.4〜v0.5.0）

### A-1. OpenJTalk セットアップの“オフライン完結”強化
**背景**
- `setup_openjtalk.ps1` は SourceForge 取得が Cloudflare で失敗するケースを想定済みだが、現場での再現性が揺れる。
- 閉域配布では「手順の分岐」が障害点になりやすい。

**提案**
- `mei_normal.htsvoice` を配布アセットとして同梱（または GitHub Release に固定配置）し、スクリプトはまず同梱ファイルを優先。
- 取得元 URL を複数候補化し、失敗理由を最終サマリに明示。
- セットアップ完了チェックを `--verify-only` モードで実装し、運用手順書に組み込む。

**期待効果**
- オフライン導入時の失敗率低減、サポート問い合わせ削減。

---

### A-2. テキスト前処理（TextPreprocessor）フェーズ3の早期実装
**背景**
- backlog #50（慣用表現）にすでに定義あり。
- 読み品質で苦情につながりやすい箇所（「3か月」「第3回」「電話番号ハイフン」）は優先度が高い。

**提案**
- ルール追加に加え、**ルール単位のテストデータファイル化**（メンテしやすい形式）を同時実施。
- 将来の誤変換対策として「変換 OFF 例（除外ケース）」もゴールデンサンプルに含める。

**期待効果**
- OpenJTalk の実用品質を段階的に底上げ。

---

### A-3. 音声保存のメモリ使用量抑制（長文 MP3/MP4）
**背景**
- `SystemSpeechEngine.SaveEncoded()` は `MemoryStream` に WAV 全体を保持してからエンコードするため、長文でメモリピークが上がる。

**提案**
- 一時 WAV ファイル経由に変更し、`WaveFileReader` でストリーミング的にエンコード。
- キャンセル時の後始末（中間ファイル削除）を明示テスト化。

**期待効果**
- 長尺原稿での安定性向上（OutOfMemory/高メモリ消費の抑止）。

---

### A-4. 例外ログの“問い合わせ即応”強化（エラーコード付与）
**背景**
- 現在もログ出力はあるが、現場報告で「どの異常か」の識別に時間がかかる。

**提案**
- 主要例外に短いエラーコード（例: `TTV-E-SETUP-001`）を付与。
- ダイアログ表示文にも同コードを表示し、問い合わせテンプレートにコード記載欄を追加。

**期待効果**
- 一次切り分けの迅速化、運用サポート工数削減。

---

## 2) 優先度B（v0.5.x）

### B-1. 音声品質評価の定例化（backlog #51 を運用フロー化）
**提案**
- SAPI / WinRT / OpenJTalk の比較評価をリリース前チェックリストに組み込む。
- 「不自然さ」「聞き取りやすさ」「固有名詞誤読率」を定点観測。

**期待効果**
- エンジン変更時の品質後退を早期検知。

---

### B-2. UI コードビハインド縮小（保守性改善）
**背景**
- `MainWindow` 系の責務が広く、変更影響範囲が大きい。

**提案**
- まずは設定保存・復元と再生制御状態（再生中/一時停止中）を ViewModel/サービスへ分離。
- 分離対象を小さく刻み、回帰テストを追加しながら段階移行。

**期待効果**
- 機能追加時の安全性向上、テストしやすさ向上。

---

### B-3. 辞書運用の事故防止（バリデーション強化）
**提案**
- CSV インポート時に「重複語」「極端な優先順位」「空読み」の検知レポートを表示。
- 取り込み結果を「成功/警告/失敗」に分類し、利用者が修正しやすい形で提示。

**期待効果**
- 現場の辞書更新ミスによる誤読を予防。

---

## 3) 優先度C（中長期）

### C-1. 設定反映タイミングの改善（再起動不要化の検討）
**背景**
- 音声エンジン切替は次回起動時反映。運用上は許容だが、試行錯誤時の体験はやや重い。

**提案**
- 「再起動して反映」方式は維持しつつ、将来的に“エンジン再初期化”による即時反映を技術検証。
- リスク（リソース解放漏れ、ハンドル競合）を先に PoC で確認。

**期待効果**
- 音声選定作業の効率化。

---

### C-2. 運用監査向けエクスポート（任意）
**提案**
- 「いつ・どのファイルを・どのエンジンで・どの形式に保存したか」の最小監査ログを CSV 出力可能にする。
- 個人情報は保持せず、ファイル名ハッシュ化や件数ベース統計を採用。

**期待効果**
- 組織内報告の定量化、監査対応の標準化。

- 最優先は **OpenJTalk セットアップのオフライン完結化**（同梱優先 + verify-only）。

- v0.5.x では品質評価定例化・UI責務分離・辞書インポート検証を進める。
