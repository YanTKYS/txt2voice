## 品質強化リリース — エンコード判定明文化・テスト拡充・CI 安定化

---

### インストール方法

1. `TxtToVoice-v0.2.4-win-x64.zip` をダウンロード
2. ZIP を任意のフォルダに展開
3. `TxtToVoice.exe` をダブルクリックして起動

> 辞書データ・設定ファイルは引き続き使えます。

---

### 変更内容

**1. テキスト読み込みのエンコード対応範囲を明文化**

ファイル読み込み（ファイルを開く / ドラッグ&ドロップ）のエンコード自動判別について、
対応範囲をドキュメントとコードコメントで明確にしました。

実装上、`File.ReadAllText` は内部で `StreamReader(detectEncodingFromByteOrderMarks: true)` を
使用しているため、以下の順でエンコードを自動判別します。

| 判定順 | 条件 | 使用エンコード |
|--------|------|--------------|
| 1 | UTF-8 BOM（EF BB BF）あり | UTF-8 |
| 2 | UTF-16 LE BOM（FF FE）あり | UTF-16 LE |
| 3 | UTF-16 BE BOM（FE FF）あり | UTF-16 BE |
| 4 | BOM なし・UTF-8 として正常 | UTF-8 |
| 5 | BOM なし・UTF-8 不正バイト列 | Shift_JIS へフォールバック |

README の「原稿を入力する」の説明も同内容に更新しました（旧: "Shift_JIS / UTF-8（BOM あり・なし）"）。

**2. パフォーマンステストの CI 環境依存対策**

`DictionaryServicePerformanceTests` に `[Trait("Category", "Performance")]` を追加し、
CI ジョブから除外できるようにしました。

```powershell
# パフォーマンステストを除いて実行
dotnet test --filter "Category!=Performance"
```

あわせて判定閾値を低スペックランナーでも安定する値に拡大しました。

| テスト | 旧閾値 | 新閾値 |
|--------|--------|--------|
| 500件辞書 × 10,000文字 | 10 秒 | 30 秒 |
| 100件辞書 × 50,000文字 | 15 秒 | 45 秒 |

**3. PathConfig / SpeechService のテストを追加**

バックログ #24 のテスト追加を実施しました。

*PathConfigTests*（9テスト）

| テスト内容 |
|------------|
| 通常モードで `IsPortable = false` であること |
| 通常モードで `PortableFallbackApplied = false` であること |
| `DataDirectory` が `%LOCALAPPDATA%\TxtToVoice` であること |
| `LogDirectory` が `DataDirectory\logs` であること |
| `DictionaryPath` / `SettingsPath` のパス整合性 |
| `IsPortable` と `PortableFallbackApplied` が同時に true にならないこと |

*SpeechServiceCancelTests*（5テスト）

音声エンジンが不在の CI 環境でも実行できる「キャンセル先行検知」テストを追加しました。

| テスト内容 |
|------------|
| キャンセル済みトークンで WAV / MP3 / MP4 保存が即 `OperationCanceledException` をスロー |
| キャンセル時に書きかけファイルが生成されないこと |
| 音声エンジン不在でも初期化が例外をスローしないこと（`IsAvailable = false` で継続） |
| `IsAvailable = false` のとき `InitializationError` が設定されること |
