## テスト構成分離・WinRT メモリ効率改善リリース

---

### インストール方法

1. `TxtToVoice-v0.3.6-win-x64.zip` をダウンロード
2. ZIP を任意のフォルダに展開
3. `TxtToVoice.exe` をダブルクリックして起動

> 辞書データ・設定ファイルは引き続き使えます。

---

### 変更概要

backlog の優先度：低（#29/#37）を対応しました。
機能変更はなく、内部品質改善（テスト構成リファクタ・メモリ効率）のみです。

---

### 変更内容

**1. テスト構成の分離・TxtToVoice.Core 新設（backlog #29）**

純ロジック層を OS 非依存プロジェクト `TxtToVoice.Core`（net8.0）に切り出しました。

- `TxtToVoice.Core` プロジェクト新設（`net8.0`、WPF/WinRT/SAPI 依存なし）
  - 移動対象: `DictionaryService` / `CsvService` / `Logger` / `PathConfig` / `AppSettingsService` / `AppSettingsBuilder` / `JsonPersistenceService` / `SsmlBuilder` / `SpeechPositionMap` / `AppSettings` / `DictionaryEntry`
  - 新規追加: `SpeechEngineTypes`（エンジン種別定数・検証を Core 層に集約）
- `TxtToVoice` は `TxtToVoice.Core` を参照
  - `SpeechEngineFactory` の定数・`IsKnown()` は `SpeechEngineTypes` に委譲（後方互換維持）
- `TxtToVoice.Core.Tests` プロジェクト新設（`net8.0`）
  - 純ロジックテスト 10 ファイルを `TxtToVoice.Tests` から移動（OS 非依存で実行可能）
- `TxtToVoice.Tests` には Windows 依存テスト（SpeechEngine 系）のみ残置
- `SpeechServiceCancelTests` に中間キャンセルテストを 2 件追加（#29B）
  - `CancellationTokenSource.CancelAfter(ms)` による遅延キャンセルのシナリオ
  - `[Trait("Category", "RequiresEngine")]` で CI 除外可能

**2. WinRT 保存処理の長文メモリ効率改善（backlog #37）**

`WinRtSpeechEngine.SaveToFile()` の `MemoryStream` を廃止し、一時 WAV ファイル経由に変更しました。

| 変更前 | 変更後 |
|---|---|
| `SpeechSynthesisStream` を `MemoryStream` に全量読み込み | `SpeechSynthesisStream` を一時 WAV ファイルに直接書き出し |
| 長文で数十〜数百 MB のメモリを一時的に消費 | ピークメモリ使用量を大幅に削減 |
| WAV: `MemoryStream → FileStream` コピー | WAV: `File.Move`（一時ファイルをそのまま移動） |
| MP3/MP4: `WaveFileReader(MemoryStream)` → エンコード | MP3/MP4: `WaveFileReader(tempWavPath)` → エンコード後に一時ファイル削除 |
