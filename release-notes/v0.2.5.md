## 監査モード完全対応リリース — 起動直後 INFO 抑制・テスト品質改善

---

### インストール方法

1. `TxtToVoice-v0.2.5-win-x64.zip` をダウンロード
2. ZIP を任意のフォルダに展開
3. `TxtToVoice.exe` をダブルクリックして起動

> 辞書データ・設定ファイルは引き続き使えます。

---

### 変更内容

**1. 監査モード INFO 抑制の起動直後適用（backlog #25）**

v0.2.3 で実装した INFO ログ抑制（`Logger.SuppressInfo`）は `LoadSettings()` で適用されていたため、
アプリ起動直後のログ（Media Foundation 初期化等）は監査モードでも記録されていました。

本バージョンで `App.OnStartup` の先頭（エンコード登録の直後）で設定 JSON を先読みし、
`Logger.SuppressInfo` を早期適用するよう修正しました。

```
起動シーケンス（修正後）:
  1. Encoding.RegisterProvider(...)         ← エンコード登録
  2. Logger.SuppressInfo = ReadAuditFlag()  ← 監査フラグ先読み ★ New
  3. MediaFoundationApi.Startup()           ← この Logger.Info も抑制対象に
  4. MainWindow 初期化 / LoadSettings()
```

`AppSettingsService.ReadAuditFlag()` を静的メソッドとして追加しました。
ファイル不在・読み込みエラー・JSON 破損のいずれの場合も `false` を返すため、
監査モードが未設定の通常起動には影響しません。

**2. SpeechServiceCancelTests のテスト品質改善（v0.2.4 レビュー対応）**

`SpeechService_初期化時に例外をスローしない` テストが
`Assert.True(svc.IsAvailable || !svc.IsAvailable)` というトートロジーになっており、
実際には何も検証していませんでした。

`Record.Exception` + `Assert.Null` を使った実効的な検証に置き換え、
初期化時に例外が発生した場合に確実に検知できるようにしました。

```csharp
// 修正前（常に true になるため検証力ゼロ）
Assert.True(svc.IsAvailable || !svc.IsAvailable);

// 修正後（例外が発生しないことを明示的に検証）
var ex = Record.Exception(() => { using var svc = new SpeechService(); });
Assert.Null(ex);
```

**3. README テスト一覧の更新（v0.2.4 レビュー対応）**

v0.2.4 で追加した `PathConfigTests.cs` と `SpeechServiceCancelTests.cs` が
README のソース構造図に掲載されていませんでした。
2 ファイルを追記し、`DictionaryServicePerformanceTests.cs` に「CI 除外可」の注記も追加しました。
